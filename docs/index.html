How it works

Turbo Julius runs on your local network. One machine is the host; everyone else connects to it.

Once Host machine

An always-on computer that stores the shared database and inventory images. You set it up one time with the included host script.

Each Workstations

Every other computer installs the app and connects to the host over the network using a short first-run wizard.

Set up the host machine

Do this once, on the computer that will store the shared data.

  1. Copy the installer folder onto the host machine.
  2. Right-click host-setup.bat and choose Run as administrator.
  3. Wait for it to finish. It installs PostgreSQL, creates the database, opens the network, and shares the files folder.
  4. Open C:\JuliusData\connection-info.txt — it lists everything the workstations need.

Full details, options, and troubleshooting are in the host setup guide.

Install on a workstation

Repeat on each computer that will use Turbo Julius.

  1. Download and run the installer using the button at the top of this page.
  2. If Windows shows a SmartScreen warning, click More info → Run anyway (see the note below).
  3. On first launch, the setup wizard opens. Choose Client workstation.
  4. Enter the database details from connection-info.txt (host IP, database, username, password) and click Test, then Connect.
  5. For file storage, choose LAN file server and enter the network path \\HOST\JuliusData (replace HOST with the host's name or IP).
  6. Finish — you're ready to go.
About the SmartScreen warning. The installer is not yet code-signed, so Windows may say the publisher is unknown. This is expected. Click More info, then Run anyway. Automatic updates still work normally.

Updates

Turbo Julius keeps itself up to date.

Each machine checks for new versions automatically. When an update has been downloaded, you'll see a prompt to Restart now or Later — the update is applied on the next restart either way. You can also check manually anytime under Settings → About → Check for updates.

Troubleshooting

A workstation can't connect to the database.
Confirm the host IP is correct and reachable (ping HOST), and that the workstation is on the same network the host script allowed. Re-run the host script with your subnet if your network uses a different range.
"Password authentication failed."
Use the exact julius_app password from connection-info.txt. Re-running the host script resets and reprints it.
Images don't appear on a workstation.
Make sure the workstation can open \\HOST\JuliusData in File Explorer and has read/write access to the share.
The host's IP keeps changing.
Reserve a static IP for the host in your router settings so workstations don't lose the connection.
